## 背景

ADR-0035 で履歴エントリの個別削除、ADR-0031 で全消去を実装したが、
どちらもボタンを押すと即座に削除された。誤って押した場合に履歴が失われる
（ADR-0031・ADR-0035 の未決定「削除の確認ダイアログ（誤操作の防止）」）。

## 決定

### 確認ダイアログ

- 個別削除・全消去のボタンは、ネイティブ `<dialog>` を `showModal()` で
  開くだけにする（独自のオーバーレイを作らない）。
- ダイアログには「Cancel」と「Delete」のボタンを置き、対象（個別／全消去）
  に応じた見出しと説明を表示する。
- 安全な操作（Cancel）に `autofocus` を付ける。
- `role="dialog"` / `aria-modal` / 手動フォーカストラップ / `inert` の
  手動切り替えは付けない。ネイティブモーダルが提供する。
- Cancel または Esc では何も削除せず、Delete を選んだときだけ削除する。
- ダイアログの `::backdrop` を半透明で覆い、モーダル中の背景スクロールを
  `overscroll-behavior: contain` で抑制する。

### 実装の分離

削除の実処理を `clear_history` / `delete_entry` に切り出し、ボタンの
ハンドラは対象を `delete_target` signal に設定してダイアログを開くだけに
する。確認ボタンが `delete_target` を見て実処理を呼ぶ。これで
「確認を挟む」ことと「削除する」ことが分離される。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| ネイティブ `<dialog>` + `showModal()`（採用） | アクセシビリティ・フォーカス・Esc 処理が標準で提供される |
| `window.confirm()` | ブラウザ標準だがスタイル制御ができず、E2E も扱いにくい |
| 独自の div オーバーレイ | フォーカストラップ等を自作する必要があり事故りやすい |

## 影響

- 削除操作に 1 段階の確認が入り、誤操作で履歴が失われにくくなる。
- 削除の実処理自体（ADR-0031・ADR-0035）は変わらない。
- 新規依存は無く、ブラウザ標準の `<dialog>` を使う。
- 平時のリーダー表示は変わらない。

## 検証

- ヘッドレス Chrome 157 と `tools/verify-web-reader.py` の E2E 146 項目が
  5 回連続で成功。削除ボタンでダイアログが開くこと、Cancel では履歴件数が
  変わらないこと、確認ボタンで削除が実行されることを確認した。既存の
  クリア・個別削除のテストも、確認ボタンを押す手順に更新して通過している。
- `cargo test --all-targets --locked` は 119 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI は billing issue で実行不可（ローカル検証で代替）。
