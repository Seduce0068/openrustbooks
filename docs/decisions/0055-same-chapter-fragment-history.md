## 背景

ADR-0017 の未決定「同一章内のフラグメント移動を履歴に含めるか」。
本文内の `#fragment` リンク（脚注への参照など）をクリックしても
スクロールするだけで履歴に積まれず、戻るボタンで元の位置へ戻れなかった
（ADR-0007 の未決定にも関連）。

## 決定

- 本文内の `#fragment` リンクをクリックしたとき、スクロールに加えて
  現在位置を履歴に記録し、移動先を新しい履歴エントリにする。
- 移動先の章は現在の章のままで、`fragment` とスクロール位置を保持する。
- 再描画は行わない（同一章なのでスクロールのみで十分）。
- 同じフラグメントへの再移動（現在の `fragment` と同じ）は履歴に積まない。
- スクロール後に実際の `scrollTop` を履歴エントリへ反映する。
- 実装は `push_history_entry` を `navigate_to` から切り出し、
  章移動と同一章フラグメント移動の両方から使う。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 履歴に記録し再描画しない（採用） | 元の位置へ戻れて無駄な再描画もない |
| `navigate_to` をそのまま使う | 同一章でも再描画が走り無駄 |
| 履歴に記録しない（現状） | 脚注から本文へ戻れない |

## 影響

- 脚注などから元の位置へ「戻る」で戻れるようになる。
- 章をまたぐリンクの挙動は変わらない（同じ `push_history_entry` を共有）。
- 同一章フラグメントの重複移動で履歴が膨らまない。

  再実行で成功）。同一章のフラグメント移動で履歴が 1 件増えること、
  移動後に戻れること、戻るで元の位置へ戻ることを確認した。
