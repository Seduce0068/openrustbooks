## 背景

`Cargo.toml` に `rust-version` が無く、CI は共通ワークフローの既定
（`stable`）に依存していた（R6 TD-M15）。
`cargo metadata` で依存の MSRV を確認すると、
`parking_lot 0.13.0` / `lock_api 0.5.0` が **1.95**、
`tauri 2.12.5` が 1.90、`rumdl 0.3.2` が 1.94 を要求していた。
また 1.95 ツールチェーンの clippy は
`core/src/epub.rs:1472` の `collapsible_match` を
`-D warnings` で失敗させた。

## 決定

- workspace と 3 member（core / desktop / web）に
  `rust-version = "1.95"` を宣言する。
- `.github/workflows/ci.yml` の `rust_toolchain` を `1.95.0` に設定し、
  ローカルと CI で同じ MSRV を使う。
- `core/src/epub.rs` の NCX `"text"` タグ処理を
  match guard 形式へ変更し、clippy 1.95 に対応する
  （挙動は不変、`_ => {}` へフォールスルー）。
- README の MSRV 表記を「Rust 1.95+」へ更新する。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 1.95（採用） | 現行ロックの依存要件に一致、実測で全ゲート成功 |
| 1.94 | parking_lot / lock_api が要求する 1.95 に届かない |
| stable 未固定 | 依存更新時に MSRV が暗黙に上昇しても検知できない |

## 影響

- MSRV を上げるため、Rust 1.94 以前ではビルドできない
  （明示的な互換性の切替）。
- `--locked` を維持するため、依存更新なしに MSRV が変わることはない。
- 共通ワークフロー（`rust-gates.yml@v1`）自体は変更しない。
- Cargo.lock は未変更（SHA-256 一致）。

## 検証（Runtime Proof）

- `rustup run 1.95.0` で以下すべて rc=0:
  - `cargo fmt --all -- --check`
  - `cargo check --all-targets --locked`
  - `cargo test --all-targets --locked`（core 261 / desktop 79 / web 2）
  - `cargo clippy --all-targets --locked -- -D warnings`
- stable（1.100.0）で `./scripts/verify.sh`: rc=0、
  E2E **253 項目すべて成功**。
- CI は billing issue で実行不可（ローカル検証で代替）。

## 未決定

- `parking_lot 0.13.x` / `lock_api 0.5.x` が将来 MSRV を上げた場合の
  依存更新戦略（`--locked` 維持なら即時影響なし）。
- MSRV を上げるたびに ADR / README / CI を手動更新する手順の自動化。
- clippy の新規 lint に対する workspace 共通の allow 方針
  （今回はコード修正で対応）。
