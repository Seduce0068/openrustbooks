## 背景

test-scanner の監査で次が判明した。

- 保存データ 0 件のとき、ステータスに警告を出すにもかかわらず
  `export_positions()` が空の JSON ファイルをダウンロードしていた。
- 文字縮小（A- ボタン、`-` キー）の動作が E2E で検証されていなかった。

## 決定

- `export_positions()` は `positions.len() == 0` のとき早期リターンし、
  Blob 生成と `<a download>` のクリックを行わない（0 を返す）。
- E2E に次を追加する。
  - 保存データ 0 件でエクスポートすると警告メッセージが出る。
  - ダウンロードファイルが生成されない。
  - A+ の後に A- で文字サイズが戻る。
  - 最小値で A- が disabled になる。
  - `-` キーでも文字サイズが小さくなる。
- 期待 check 総数を 228 に更新する。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 0 件で早期リターン（採用） | 警告と実際の挙動が一致し、空ファイルが消える |
| 空ファイルを出力し続ける | 利用者を混乱させる |
| 設定・履歴だけを出力 | 「保存データなし」という警告と矛盾する |

## 影響

- 保存データが無いときに空ファイルがダウンロードされなくなる。
- 文字縮小の回帰が E2E で検出できる。
- 既存のエクスポート（データあり）は変わらない。

## 検証

- E2E 228 項目がすべて成功。
  - 追加 5 件（空エクスポート 2 件、文字縮小 3 件）。
- `cargo fmt --all` / `trunk build --offline` が成功。
- `./scripts/verify.sh` を実行し、6 ゲート・trunk build・WASM パス検査・
  E2E 228 項目がすべて成功した。
