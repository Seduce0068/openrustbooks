## 背景

ADR-0036 / 0049 / 0063 の未決定「形式バージョン 2 以降のマイグレーション方針」。
現在は version 1（および version 無しの旧形式）のみを受け付け、
未知のバージョンは拒否する（fail-closed）。将来形式を拡張するときに
旧ファイルを誤って壊さないための判断指針が必要。

## 決定

### version 2 を導入する条件

- version 1 のデータモデル（positions / settings / history）では表現できない
  情報が必要になったときに限り、version を 2 に上げる。
- 単なるフィールド追加で既存 reader が安全に読める場合は、version を上げずに
  省略可能なキーとして追加する（serde の `default` で吸収できるため）。

### 受け付けるバージョン範囲

実装が version N をサポートする場合、次を受け付ける。

| version | 扱い |
| --- | --- |
| キー無し | 旧形式として受け付ける（ADR-0036）。 |
| 1 | 受け付ける。 |
| 2 | version 2 以降の実装で受け付ける（version 1 も引き続き受け付ける）。 |
| 0 または実装が知らない値 | 拒否する（fail-closed）。 |

「1 つ前のバージョンまで受け付ける」方針とし、それより古い形式は
拒否して既存データを守る。version 1 のファイルは version 2 / 3 の
実装でも読み込めるようにする（後方互換を維持する）。

### version 2 固有フィールドの欠落

- version 1 のファイルに version 2 のキーが無い場合は、serde の `default`
  で既定値を入れる。
- 既存の `ReaderSettings` / `SavedHistory` と同じパターンを使い、
  欠落キーごとに専用の default 関数を設ける。

### version 1 → 2 の移行手順

1. version 2 の reader を、version 1 と 2 の両方を読み込める形で実装する。
2. 利用者が version 1 のバックアップをインポートすると、内部で
   version 2 相当のデータへ正規化される。
3. 次回エクスポート時は version 2 で書き出される（ADR-0069 / 0070 の
   タイムスタンプ付きファイル名で、旧ファイルと区別できる）。
4. 旧 reader で version 2 ファイルを開くと拒否される。これは安全な動作であり、
   利用者は新しい reader を使うよう案内する。

### 未知バージョンを拒否する理由

未知のフィールドを無視して取り込むと、意味の異なるデータを誤って適用し、
読書位置や履歴を壊す恐れがある。拒否なら既存データは無傷で残る
（ADR-0036 の fail-closed 方針を維持する）。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 1 つ前まで受け付け（採用） | 互換性と実装コストのバランスが良い |
| 全バージョンを受け付ける | 古い形式の意味変更を吸収できず危険 |
| 現行バージョンのみ | 旧バックアップが突然読めなくなる |

## 影響
