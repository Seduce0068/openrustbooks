## 背景

ADR-0034 の未決定「画像のデコード・縮小（大きな画像のメモリ使用）」。
本文画像は `max-width: 100%` で表示縮小されるが、メモリ上は元のピクセル
（例: 4000px）が保持される。いきなり縮小すると既存 E2E やスクロール位置
補正に影響するため、まず巨大画像を検出して利用者に知らせる。

## 決定

- 位置適用の完了時に本文の `<img>` を走査し、`naturalWidth` または
  `naturalHeight` が 4000px を超える画像を検出する。
- 検出した場合は状態メッセージ
  `Large image detected (WxH). Consider a smaller source.` を表示する。
- 警告は表示のみで、画像の差し替え・スクロール位置の変更は行わない。
- 閾値ちょうど（4000px）は警告対象にしない（既存サンプルを壊さない）。
- 位置適用コンテキストに状態更新用クロージャを持たせ、適用完了時に
  警告を出す（章描画直後の `set_status("")` の後に反映される）。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 検出して警告（採用） | 既存機能を壊さず、利用者が原因を把握できる |
| 自動で縮小 | 既存 E2E（naturalHeight === 4000）や位置補正に影響する |
| 何もしない | メモリ使用量の原因が分からない |

## 影響

- 巨大画像を含む本を開くと、状態メッセージで警告が出る。
- 画像の表示そのものは変わらない。
- 追加依存は無く、既存の DOM API だけを使う。

## 検証

- ヘッドレス Chrome 157 と `tools/verify-web-reader.py` の E2E 187 項目が
  5 回連続で成功。既存サンプル（4000px）では警告が出ないこと、
  E2E 内で生成した 5000px の画像で警告が出ることを確認した。
- 警告の表示は画像読み込みから約 1 秒後だったため、テストは固定待ちではなく
  `wait_until` で待つよう修正した。
- `cargo test --all-targets --locked` は 124 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI は billing issue で実行不可（ローカル検証で代替）。
