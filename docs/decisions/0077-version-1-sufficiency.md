## 背景

ADR-0076 の未決定「version 2 で追加する具体的なフィールド（現時点で必要な情報は無い）」。
ADR-0076 の方針では、version 1 のデータモデルで表現できない情報が必要になった
ときにのみ version を上げる。現時点でそのような要件が無いことを確認する。

## レビュー

現在のエクスポート形式（version 1）は次を含む。

- `positions`: 章インデックス、フラグメント、スクロール位置、保存時刻
- `settings`: 文字サイズ、行間、ダーク、OS 追従、スワイプ閾値（横・縦）、
  画像縮小、JPEG 品質
- `history`: 章インデックス、フラグメント、スクロール位置、保存時刻、現在位置

実装済みの機能（読書位置・履歴・表示設定の保存と復元、ラウンドトリップ、
マージ）はすべてこのモデルで表現でき、E2E 206 項目で検証済み。

## 決定

- 現時点では **version 1 を維持する**。version 2 は導入しない。
- ADR-0076 の導入条件（version 1 では表現できない情報が必要になったとき）
  は満たしていない。
- 将来 version 2 が必要になる可能性のある候補を記録する（下記「未決定」）。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| version 1 を維持（採用） | 必要な情報がすべて表現でき、互換性を保てる |
| 今のうちに version 2 を定義 | 追加する情報が未定で、形式的な変更になる |

## 影響

- コード変更は無い。
- 既存のバックアップ形式はそのまま使える。
- 既存の 125 テスト、E2E 206 項目はそのまま通る。

## 検証

- `cargo test --all-targets --locked` は 125 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI は billing issue で実行不可（ローカル検証で代替）。

## 未決定（version 2 の候補）

次が必要になったときに version 2 を検討する（ADR-0076 の方針に従う）。

- 複数の本（複数ボックス）の状態を 1 つのファイルにまとめる要件。
- 注釈・ハイライト・しおりの保存。
- 外部ストレージ（URL やクラウド ID）への参照。
- 形式の暗号化や署名。

いずれも現時点では要件として確定していない。
