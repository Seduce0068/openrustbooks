## 背景

ADR-0136 / 0137 は、width/height 属性付与の前に
ADR-0020 / 0037 / 0046 の位置復元系 E2E をベースライン化するよう求めていた。

## 実行結果（e2e-baseline-runner）

- `trunk build --offline` を実行済み（生成物のみ更新、ソース無変更）。
- 5 回連続の結果:

| 回 | 結果 |
| --- | --- |
| 1 | passed: 229, failed: 0 |
| 2 | passed: 229, failed: 0 |
| 3 | passed: 229, failed: 0 |
| 4 | passed: 228, failed: 1（`5000px の画像で警告が出る`、`status=''`） |
| 5 | passed: 229, failed: 0 |

- 追加 2 回の再実行はいずれも passed: 229, failed: 0。
- 位置復元関連チェック（例: `位置の適用は画像の読み込み完了を待つ`、
  `フラグメント付きの位置が復元される`、
  `画像読み込み後も復元位置が同じ内容を指す`）は 5 回すべて成功。

## 決定

- 今回の 5 回を **スモークベースライン**として記録する。
- 位置復元系は全回成功したため、現状の挙動は安定していると判断する。
- フレークは画像警告の表示タイミングに限局しており、
  位置復元とは無関係として切り分ける。
- 画像寸法予約の実装後、同じ 229 チェックを再実行し、
  位置復元系の 30px / 50px 許容値と `attempts` を比較する。

## 統計的限界（e2e-baseline-auditor の指摘）

- 過去のフレーク率は 10〜20% 程度と推定され、5 回連続成功でも
  欠陥を否定できない（**推測**による二項計算）。
- 位置復元系は ADR-0046 / 0054 の前例に従い最低 10 回、
  フラグメントスクロールは ADR-0053 の前例に従い 20 回の実行が望ましい。
- 今回の 5 回は「寸法予約前のスモーク」であり、実装前の最終ゲートではない。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 5 回をスモークとして記録（採用） | 現状の挙動とフレーク箇所を切り分けられる |
| 5 回でベースライン確定 | 統計的に不十分で却下 |
| 実装を先に進める | 回帰テストが無く安全第一でない |

## 検証

- 全テストは 246 件（native）+ wasm 3、audit 脆弱性 0 件を維持。
- コード変更なし（trunk build の生成物のみ）。
- CI は billing issue で実行不可（ローカル検証で代替）。
