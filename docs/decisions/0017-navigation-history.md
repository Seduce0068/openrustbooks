## 背景

ADR-0016 までで章・フラグメント・スクロール位置の保存と復元はできるが、
読書中の移動を戻る手段が無かった（ADR-0015・ADR-0016 の未決定「戻る・進むの
履歴」）。目次や本文内リンクで移動した後、前の位置へ戻るには目次から
探し直す必要があった。

## 決定

### 履歴

- 履歴はメモリ上のスタック（`Vec` + 現在位置）で保持し、最大 50 件とする。
  上限を超えたら古いものから捨てる。
- 章を移動する操作（目次選択・前後章・相対リンクの章移動）で、移動先を
  履歴に積む。移動前の現在位置（スクロール位置）は履歴の現在エントリへ
  記録する。
- 戻る・進むは履歴上の位置へ移動し、スクロール位置も復元する。
- 戻った後に新しい移動をすると、進む方向の履歴は捨てる。
- 本を開き直したら履歴をリセットし、初期位置を 1 件だけ積む。
- 履歴はメモリ上だけで保持し、localStorage へは保存しない。

### UI

ツールバーに `Back` / `Forward` ボタンを置き、移動できないときは `disabled`
にする。ボタンには E2E 用に `id="reader-back"` / `id="reader-forward"` を付ける。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| メモリ上の履歴スタック（採用） | 実装が小さく、読書位置の保存と独立。セッション内の移動には十分 |
| localStorage に履歴を保存 | 再起動後も戻れるが、容量・整合性・プライバシーの管理が増える |
| ブラウザの History API | URL と状態の同期が必要で、SPA のルーティングと衝突しやすい |
| 履歴を持たない | 目次から探し直す必要があり、読書の連続性が損なわれる |

## 影響

- 章移動の後でも Back / Forward で行き来できる。
- 履歴はタブを閉じると消える。
- 同一章内のフラグメント移動は履歴に積まず、スクロール位置の更新だけを行う。
- 履歴の上限 50 件でメモリ使用を抑える。
