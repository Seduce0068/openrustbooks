## 背景

`docs/requirements.md` の品質要件に「日本語IME、タッチ操作、キーボード操作を
検証する」があるが、リーダーはクリックとキーボードだけで操作でき、タッチ
デバイスではスワイプで章を移動できなかった（ADR-0021 の未決定「タッチ操作・
ジェスチャーの対応」）。

## 決定

### スワイプ

- 本文領域（`.reader-content`）の `touchstart` / `touchend` を監視する。
- 水平方向の移動が 50px 以上、垂直方向の移動が 30px 未満のときスワイプと
  判定する。
- 左スワイプ（指を左へ動かす）で次の章、右スワイプで前の章へ移動する。
- 縦スクロール中のジェスチャーは無視する（垂直移動が 30px 以上）。
- マルチタッチ（2本指以上）は無視する。
- スワイプ中は `prevent_default` しない（縦スクロールを妨げない）。

### ARIA

本文領域の `aria-label`・`role`・`tabindex` は既存のまま維持する。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| `touchstart` / `touchend` の差分判定（採用） | 追加依存なし、実装が小さい |
| `touchmove` を追ってリアルタイム判定 | 実装が複雑で、スクロールと競合しやすい |
| 外部ライブラリ（hammer.js 等） | 依存が増える。単純なスワイプには過剰 |
| スワイプを実装しない | タッチデバイスでの操作性が損なわれる |

## 影響

- タッチデバイスでスワイプによる章移動ができる。
- 縦スクロールとスワイプを区別するため、閾値（50px / 30px）を設ける。
- 追加依存は無く、既存の `web-sys` 機能の範囲で実装している。

## 検証

- ヘッドレス Chrome 157 と `tools/verify-web-reader.py` の E2E 101 項目が
  3 回連続で成功。タッチについて、左スワイプでの次章移動、右スワイプでの
  前章移動、縦移動が大きいジェスチャーの無視、マルチタッチの無視を確認
  した。
- `cargo test --all-targets --locked` は 119 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI（`Seduce0068/workflows/rust-gates.yml@v1`）が成功する。
