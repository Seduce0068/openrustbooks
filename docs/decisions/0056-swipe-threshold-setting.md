## 背景

ADR-0025 の未決定「スワイプの閾値を設定で変更できるようにするか」。
章移動の閾値 50px・縦スクロール判定 30px がハードコードされており、
端末や利用者の操作感に合わせられなかった。

## 決定

- `ReaderSettings` に `swipeThreshold` を追加する。既定値 50、範囲 30〜120px。
- 既存の設定 JSON にキーが無い場合は既定値 50 として読む（後方互換）。
- 範囲外の値は `normalized()` で 30〜120 にクランプする。
- 設定の保存・エクスポート・インポートに含まれる（既存の仕組みをそのまま利用）。
- ツールバーに数値入力（`<input id="reader-swipe-threshold">`）を置き、
  変更で即座に保存・反映する。
- 章移動の横スワイプ判定に設定値を使う。縦スクロール判定の 30px は維持する。
- 履歴処理を `push_history_entry` に切り出した ADR-0055 の構成と同様、
  設定の永続化は `persist_settings` を共有する。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 設定で変更可能にする（採用） | 端末・利用者に合わせられる |
| ハードコードのまま | 操作感を調整できない |
| プリセット（低/中/高） | 数値入力より自由度が低い |

## 影響

- スワイプの感度を利用者が調整できる。
- 表示設定の JSON に `swipeThreshold` が 1 つ増える。旧データは既定値で読める。
- 追加依存は無く、既存の `web-sys` 機能の範囲で実装している。

## 検証

- ヘッドレス Chrome 157 と `tools/verify-web-reader.py` の E2E 172 項目が
  5 回連続で成功。閾値入力の存在、変更値（80）の保存、範囲外（999）の
  120 へのクランプを確認した。
- `cargo test --all-targets --locked` は 121 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI は billing issue で実行不可（ローカル検証で代替）。
