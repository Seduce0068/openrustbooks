## 背景

ADR-0049 でエクスポート→インポートのラウンドトリップを検証したが、
旧形式（version 無し）のファイルをインポートした後のエクスポートや、
savedAt マージがラウンドトリップで壊れないことは未検証だった
（ADR-0041 の未決定）。旧形式とマージは個別には検証済みだが、連鎖は未確認。

## 決定

- E2E に旧形式のラウンドトリップ連鎖を追加する。
  - 旧形式（version 無し、positions のみ）の JSON をインポートし、
    位置（scrollTop=17）が復元されることを確認。
  - その状態でエクスポートし、`version: 1` と旧形式由来の位置キーが
    含まれることを確認。
  - エクスポートファイルを再インポートし、位置が残ることを確認。
- プロダクションコードは変更しない（テスト追加のみ）。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 連鎖を E2E で検証（採用） | 旧データの移行経路を end-to-end で確認できる |
| 個別テストだけで済ませる | エクスポート側の version 付与との連携を見逃す |
| 旧形式のエクスポートを追加 | 新規ファイルに旧形式を出す理由が無い |

## 影響

- 旧形式バックアップからの移行経路が回帰から保護される。
- プロダクションコードの挙動は変わらない。
- 追加依存は無く、既存の CDP ダウンロード機能を使う。

## 検証

- ヘッドレス Chrome 157 と `tools/verify-web-reader.py` の E2E 185 項目が
  5 回連続で成功。旧形式インポートでの位置復元、エクスポートでの
  `version: 1` 付与、再インポートでの位置保持を確認した。
- `cargo test --all-targets --locked` は 124 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI は billing issue で実行不可（ローカル検証で代替）。
