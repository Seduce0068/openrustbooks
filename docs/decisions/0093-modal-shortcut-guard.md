## 背景

削除確認ダイアログやショートカットヘルプが開いているときも `key_handler` が
動作し、背景の章移動やダーク切替が起こる可能性があった
（todo.md B04-B07 / C01 の一部）。

## 決定

- `key_handler` の先頭で `dialog[open]` が存在すれば return する。
- Esc はネイティブ dialog の標準動作に任せる（既存どおり）。
- `?` キーでヘルプを開く処理はガードの後に置かれているため、
  ダイアログが閉じているときだけ動作する。
- E2E で、ヘルプ表示中に `d` を押してもダーク表示が変わらないことを確認する。
- 期待 check 総数を 223 に更新する。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| `dialog[open]` を検出（採用） | 既存のネイティブ dialog をそのまま活用できる |
| 独自フラグ管理 | ダイアログ追加時に更新漏れが起きる |
| モーダル中もショートカット有効 | 背景が意図せず操作される |

## 影響

- モーダル表示中は背景のショートカットが止まる。
- 通常のキーボード操作・IME ガードは変わらない。
- 追加依存は無い。

## 検証

- E2E 223 項目を 5 回連続実行し、すべて成功。
- `./scripts/verify.sh` を実行し、6 ゲート・trunk build・WASM パス検査・
  E2E 223 項目がすべて成功した。
- CI は billing issue で実行不可（ローカル検証で代替）。
