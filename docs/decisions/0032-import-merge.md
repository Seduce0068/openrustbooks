## 背景

ADR-0026・ADR-0030 まででインポートは同キーを常に上書きしていた。古い
バックアップを読み込むと、現在の読書位置が古い値で壊れる
（ADR-0026 の未決定「インポート時のマージ（上書きではなく統合）」）。

## 決定

### 位置のマージ

- インポートする位置キーが localStorage に既に存在する場合、
  `savedAt` を比較して新しい方を採用する。
- 既存の `savedAt` の方が新しい（または等しい）場合は既存を維持し、
  取り込み件数に数えない。
- 既存の値が `SavedPosition` として読めない場合は、インポート値で
  上書きする（現在の挙動と同じ）。
- `settings` と `history` は従来どおりインポート値で上書きする
  （位置のマージの対象外）。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| savedAt による新しい方採用（採用） | 単純で予測可能、古いバックアップで現在位置が壊れない |
| 常に上書き（現状） | 古いバックアップで現在位置が壊れる |
| 統合（フィールド単位マージ） | どちらの値を採用するかのルールが複雑になる |

## 影響

- 古いバックアップをインポートしても、現在の読書位置が新しい値を維持する。
- インポートの状態メッセージの文言は変わらない（取り込み件数は
  新しく採用された位置のみ数える）。
- 追加依存は無く、既存の `web-sys` 機能の範囲で実装している。

## 検証

- ヘッドレス Chrome 157 と `tools/verify-web-reader.py` の E2E 123 項目が
  3 回連続で成功。インポートのマージについて、既存の savedAt が新しい
  位置が上書きされないこと、既存キーが無い位置が取り込まれることを確認した。
- `cargo test --all-targets --locked` は 119 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI は billing issue で実行不可（ローカル検証で代替）。
