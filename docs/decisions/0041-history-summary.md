## 背景

ADR-0029 で履歴一覧からのジャンプ、ADR-0035 で個別削除を実装したが、
一覧のラベルは章タイトルのみで、いつその位置を訪れたか分からなかった
（ADR-0031・ADR-0035 の未決定「章をまたぐ履歴のサマリー表示（日時つき）」）。

## 決定

### 履歴への日時記録

- `HistoryEntry` と `SavedHistoryEntry` に `saved_at`（エポックミリ秒、
  JSON では `savedAt`）を追加する。
- 章へ移動したとき（`navigate_to`）の時刻を記録する。
- 旧データに `savedAt` が無い場合は `0` として読む（serde の `default`）。
  後方互換のため、既存のバックアップもそのまま読み込める。

### 一覧ラベル

- 各エントリのラベルを「章タイトル（#フラグメント） — 日時」にする。
- 日時はローカルタイムゾーンの `YYYY-MM-DD HH:MM` 形式（`js_sys::Date`
  のローカルな getter を使用）。
- `savedAt` が 0 の旧データは日時部分を省略する。

### 実装の詳細

- 履歴一覧の UI 用 signal `history_entries` を 4 タプル
  `(履歴インデックス, 章インデックス, フラグメント, 保存時刻)` に拡張する。
- `For` の key からは `f64`（`Eq` / `Hash` を実装しない）を除外し、
  従来どおり `(インデックス, 章インデックス, フラグメント)` を使う。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| エポックミリ秒を保存し表示時に整形（採用） | タイムゾーンに依存せず保存できる |
| 整形済み文字列を保存 | 表示形式を変えられない |
| 日時を保存しない（現状） | いつ訪れたか分からない |

## 影響

- 履歴の保存 JSON に `savedAt` が 1 つ増える。旧データの読み込みは
  `default` により維持される。
- エクスポート・インポート（ADR-0030）も同じ `SavedHistory` を使うため、
  バックアップにも日時が含まれる。
- 追加依存は無く、既存の `web-sys` 機能の範囲で実装している。

## 検証

- ヘッドレス Chrome 157 と `tools/verify-web-reader.py` の E2E 147 項目が
  5 回連続で成功。章移動後に履歴一覧のラベルへ `YYYY-MM-DD HH:MM` 形式の
  日時が表示されることを確認した。
- `cargo test --all-targets --locked` は 119 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI は billing issue で実行不可（ローカル検証で代替）。
