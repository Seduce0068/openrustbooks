## 背景

ADR-0031 までで履歴の全消去（クリア）はできたが、任意の 1 件だけを消す手段が
無かった（ADR-0029・ADR-0031 の未決定「履歴エントリの個別削除」）。一部の
エントリだけが不要な場合に全消去では必要な履歴まで失われる。

## 決定

### 個別削除ボタン

- ツールバーに `<button id="reader-history-delete" aria-label="Delete history entry">`
  を置く。ラベルは "Delete"。
- クリックで現在選択中の履歴エントリ（`history_index` が指すもの）を
  履歴から削除する。
- 削除後も表示中の章・スクロール位置は変えない（再描画しない）。
  これは「履歴の整理」と「読書位置の移動」を分離するため。
- 削除後の `history_index` は次のとおり調整する。
  - 削除した位置より後ろにエントリがある場合は同じインデックス
    （次のエントリが繰り上がる）。
  - 削除した位置が最後の場合は 1 つ前のインデックス。
- localStorage の当該本の履歴キーも更新する。
- 履歴が 1 件のときは disabled にする（履歴を空にしない）。
  履歴が完全に空になると、次の移動の起点が消えて戻る・進む・一覧の
  意味が失われるため（ADR-0031 と同じ理由）。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 選択中エントリの削除ボタン（採用） | 既存の一覧とクリアの UI に自然に追加できる |
| 一覧の各行に削除ボタン | ドロップダウンでは行ごとのボタンを置けない |
| 全消去だけ（現状） | 必要な履歴まで失われる |

## 影響

- 不要な履歴エントリだけを消せる。
- 履歴の保存・復元の仕組み（ADR-0024）、エクスポート・インポート
  （ADR-0030）は変わらない。削除後の履歴も通常どおりバックアップ対象。
- 追加依存は無く、既存の `web-sys` 機能の範囲で実装している。

## 検証

- ヘッドレス Chrome 157 と `tools/verify-web-reader.py` の E2E 136 項目が
  5 回中 4 回成功。残り 1 回は既存の画像読み込み待ちテストが
  タイミングで失敗したが、attempts の記録では画像は最終的に
  `complete: true` になっており、今回の削除機能とは無関係。
  個別削除について、ボタンの存在、削除で 1 件減ること、削除後も表示中の
  章が変わらないこと、1 件まで減らせること、1 件のとき disabled になる
  ことを確認した。
- `cargo test --all-targets --locked` は 119 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI は billing issue で実行不可（ローカル検証で代替）。
