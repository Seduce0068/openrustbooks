## 背景

ADR-0014 は本文内の相対リンクで章を移動できるようにしたが、リーダーを開き
直すたびに先頭の章へ戻っていた（ADR-0012・ADR-0014 の未決定）。読書の
連続性のため、本ごとに最後に読んでいた章とフラグメントを覚えておく。

保存先はブラウザ内で完結する localStorage とし、外部送信は行わない。

## 決定

### 保存

- 本の識別子は `File.name()`・`File.size()`・`File.lastModified()` から作る。
- localStorage のキーは
  `openrustbooks:position:<name>:<size>:<lastModified>`。
- 値は JSON `{"chapterIndex": N, "fragment": "..." | null}`。
- 章を表示するたびに保存する（目次・前後移動・相対リンク・復元を含む）。
- 同じ章内のフラグメント移動でもフラグメントを保存する。
- localStorage が使えない・値が壊れている場合は黙って諦め、表示を妨げない。

### 復元

- 本を開いたとき、保存された位置があり `chapterIndex` が章数の範囲内なら
  その章を表示する。範囲外なら先頭の章にする。
- 復元時もフラグメントがあればスクロールする（ADR-0014 の描画後スクロール）。
- 保存が無い本は従来どおり先頭の章。

### プライバシー

- 保存するのは章の index とフラグメントのみ。ファイル内容・本文は保存しない。
- 外部送信を追加しない。新規依存を追加しない。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| localStorage（採用） | 追加依存なし、ブラウザ内で完結し、実装が小さい |
| IndexedDB | 非同期で複雑。単一の小さな値には過剰 |
| URL のフラグメント・クエリに保存 | 本の識別や共有時の扱いが増える |
| ファイル内容のハッシュをキーにする | 大きな本で読み込み時の計算コストが増える。サイズと更新時刻で代替する |
| 保存しない | 開くたびに先頭へ戻り、読書の連続性が損なわれる |

## 影響

- 同じ本を開き直すと、前回の章とフラグメントから再開できる。
- 保存値は本ごとに 1 件。ブラウザの localStorage を消すと失われる。
- 名前・サイズ・更新時刻がすべて同じ別ファイルは位置を共有し得る（限定的）。
- ファイルを編集すると `lastModified` が変わり、位置は引き継がれない。
- 章内のピクセル単位のスクロール位置は保存しない。

  読書位置について、保存値が `{chapterIndex, fragment}` だけであること、
  章の移動で保存されること、リロード後の復元、フラグメント付きの復元と
  スクロール、範囲外の保存値での先頭章フォールバックを確認した。
