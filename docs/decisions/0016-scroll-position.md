## 背景

ADR-0015 は章とフラグメントを保存・復元するようにしたが、章内のスクロール
位置は保存しないため、長い章では毎回先頭から読み直すことになっていた
（ADR-0015 の未決定）。章内の位置も保存して再開できるようにする。

## 決定

### 保存

- `SavedPosition` に `scrollTop`（整数、px）を加える。旧形式の保存値に
  無い場合は 0 として読む（`serde(default)`）。
- `.reader-content` の `scroll` イベントで、200ms のデバウンス後に
  `{chapterIndex, fragment: null, scrollTop}` を保存する。
- デバウンス中に章が切り替わった場合は書き込まない（古い章の位置で
  新しい章の保存値を上書きしない）。
- 保存するのは章の index とスクロール位置だけで、本文・内容は保存しない。

### 復元

- 描画後の `requestAnimationFrame` で位置を適用し、適用後の実際の位置を
  保存する。
- フラグメントがあればフラグメントへスクロールする（ADR-0014 の動作）。
- フラグメントが無く `scrollTop > 0` なら、`.reader-content` をその位置へ
  スクロールする。
- どちらも無ければ先頭へスクロールする。
- レイアウトが終わっておらず位置が反映されないことがあるため、要求した
  位置に届くまで最大 3 フレーム再試行する。

### 章の切り替え

目次・前後移動・相対リンクで章を切り替えたときは、先頭（フラグメント指定時は
その位置）へスクロールし、保存値も新しい章の位置にする。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| localStorage に `scrollTop` を追加（採用） | 追加依存なし。既存の保存形式を後方互換に拡張できる |
| 段落や見出しの位置を保存する | レイアウト変化に強いが、位置の対応付けの実装が大きい |
| スクロールのたびに保存する | 書き込みが多すぎる。200ms のデバウンスで抑える |
| 保存しない | 長い章で毎回先頭から読み直しになる |

## 影響

- 長い章でも前回のスクロール位置から再開できる。
- 保存値は `{chapterIndex, fragment, scrollTop}` になる。
- 画像の読み込みなどでレイアウトが変わると、復元位置がずれる可能性がある。
- 章を切り替えるとスクロール位置は先頭（またはフラグメント）に戻る。
