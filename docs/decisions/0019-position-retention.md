## 背景

ADR-0018 までで読書位置を localStorage に保存するようにしたが、保存件数の
上限が無く、本を読み続けると `openrustbooks:position:` のキーが増え続ける。
localStorage の容量は有限で、上限に達すると保存が失敗し、読書位置が
更新されなくなる（ADR-0016・ADR-0018 の未決定）。

## 決定

### 保存時刻

- `SavedPosition` に `savedAt`（Unix ミリ秒、`f64`）を加える。旧形式の
  保存値に無い場合は 0 として読む（`serde(default)`）。
- 保存時に現在時刻を書き込む。

### 掃除

保存のたびに `prune_positions` を実行する。

- 寿命: `savedAt` が 90 日より古いエントリを削除する。
- 件数: 40 件を超える場合、`savedAt` の新しい順に 40 件を残す。
- `savedAt` が 0 の旧形式エントリは寿命判定の対象にせず、件数上限では
  最も古いものとして扱う。
- 現在開いている本のキーは必ず残す。
- `openrustbooks:settings` など読書位置以外のキーには触らない。
- 定期実行のタイマーは設けず、保存時にだけ走らせる。

### 容量超過

- `set_item` が失敗した場合、古い順に 10 件、次に 1 件まで減らして
  再試行する。それでも失敗したら諦め、読書を妨げない。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 保存時の掃除 + 件数・寿命（採用） | 追加のタイマーやイベントが不要で、保存経路だけで完結する |
| IndexedDB で容量を増やす | 非同期化と移行が必要。単一の小さな値には過剰 |
| 定期的なタイマー掃除 | 読書中でないタブでも動き、実装と検証が増える |
| 上限なし | 保存失敗で読書位置が更新されなくなる |

## 影響

- 使わなくなった本の読書位置は 90 日で消える。よく読む本の位置は残る。
- 41 冊以上を並行して読むと、古い本の位置から消える。
- 保存値は `{chapterIndex, fragment, scrollTop, savedAt}` になる。
- 容量超過時は古い位置を捨ててでも現在の本の保存を優先する。
