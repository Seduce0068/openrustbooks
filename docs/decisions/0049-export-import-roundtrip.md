## 背景

ADR-0026 / 0030 / 0032 / 0036 でエクスポート・インポートを拡張してきたが、
E2E では「エクスポートボタンの存在」と「個別のインポート」しか検証しておらず、
実際に書き出したファイルをそのまま読み込めることを確認していなかった。
形式バージョン（ADR-0036）や `savedAt`（ADR-0041）を含めた包括了な回帰
テストが必要だった。

## 決定

- E2E にラウンドトリップ検証を追加する。
  - CDP の `Browser.setDownloadBehavior` でダウンロード先を設定し、
    エクスポートボタンで書き出した JSON ファイルを取得する。
  - ファイルに `version: 1` / `positions` / `settings` / `history` が
    含まれることを検証する。
  - 書き出したファイルをそのまま `#reader-import-file` にセットして
    インポートし、設定・履歴・読書位置が復元されることを検証する。
  - ダウンロードディレクトリは後始末で削除する。
- プロダクションコードは変更しない（テスト追加のみ）。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 実際にダウンロードしたファイルを再インポート（採用） | 形式の整合性を end-to-end で確認できる |
| エクスポート関数を直接呼んで文字列を検証 | wasm 内部の関数を E2E から呼べない |
| 個別のインポートテストだけで済ませる | 書き出し側の変更（version 等）を見逃す |

## 影響

- エクスポート・インポートの形式変更に対する回帰検証が強化される。
- プロダクションコードの挙動は変わらない。
- 追加依存は無く、既存の CDP 機能だけを使う。

## 検証

- ヘッドレス Chrome 157 と `tools/verify-web-reader.py` の E2E 166 項目が
  5 回連続で成功。エクスポートファイルに `version: 1` / `positions` /
  `settings` / `history` が含まれ、そのファイルをそのままインポートして
  設定（fontScale=2）・履歴・読書位置が復元されることを確認した。
- `cargo test --all-targets --locked` は 119 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI は billing issue で実行不可（ローカル検証で代替）。
