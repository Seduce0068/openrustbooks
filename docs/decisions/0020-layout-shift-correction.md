## 背景

ADR-0016・0019 までで章内のスクロール位置を保存・復元するようにしたが、
画像は Blob URL で非同期に読み込まれるため、復元の時点では画像の高さが
未確定のことがあった。画像が後から入ると本文が押し下げられ、保存した
`scrollTop` が別の内容を指す。

実測では、待機を外すと 4000px 相当の画像章で `complete: false` のまま位置を
適用し、画像の高さぶん位置がずれた。

## 決定

### 位置適用前の待機

- `.reader-html img` のうち `src` があるものが、設定した HTML の `img` 数
  （`expected_images`）だけ DOM に現れ、すべて `complete` になるまで位置の
  適用を待つ。本文の更新は非同期に DOM へ反映されるため、数が揃うまでは
  未確定として扱う。
- 待ち時間の上限は 2000ms とし、超えたら確定したレイアウトで適用する。
- フラグメント指定と `scrollTop` 指定の両方で待つ。
- `src` が無い画像（解決できず除去したもの）は待たない。
- 待機後も要求位置に届かない場合は、従来どおり数フレーム再試行する。

### フラグメント保存の欠落修正

適用中のフラグメントを `current_fragment` に保持し、スクロールのデバウンス
保存が `fragment: None` で上書きしないようにした。実測では、フラグメント
移動の直後にスクロール保存が走り、保存値の `fragment` が消えていた。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 画像の `complete` と枚数を待つ（採用） | 追加依存なし。Blob URL の読み込み完了を直接観測できる |
| `load` イベントを全部待つ | 解決できず `src` を消した画像で永遠に待つ危険がある |
| `ResizeObserver` で本文の高さ変化を監視 | 監視の解除とループの制御が増える |
| 待たない | 画像の高さぶん位置がずれる（実測で再現） |

## 影響

- 画像を含む章でも、復元位置が同じ内容を指す。
- 画像の読み込みが遅い場合は最大 2000ms だけ位置の適用が遅れる。
- フラグメント付きの保存値が、その後のスクロールで消えなくなる。
- 追加依存は無く、既存の `web-sys` 機能の範囲で実装している。

## 検証

- ヘッドレス Chrome 157 と `tools/verify-web-reader.py` の E2E 73 項目が
  7 回連続で成功。
- 判別力の確認: 待機を 0ms にしたビルドでは
  「位置の適用は画像の読み込み完了を待つ」が失敗する（`complete: false` で
  位置を適用）。
- 判別力の確認: フラグメント保持を外したビルドでは
  「スクロール保存後もフラグメントが残る」が失敗する。
- 画像の前後で `#part` の位置が保存時と一致すること（許容 30px）を確認。
- `cargo test --all-targets --locked` は 119 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI（`Seduce0068/workflows/rust-gates.yml@v1`）が成功する。
