## 背景

ADR-0052 で、フラグメントスクロールが約 1/10 の頻度で `scrollTop=0` になる
問題を調査し、`set_scroll_top(2375)` 自体は成功しているが、E2E が読む時点で
0 に戻っていることを確認していた。原因は特定できていなかった。

## 調査

E2E に `MutationObserver` と `scroll` イベントの監視を追加して失敗を再現した。

- 失敗時も `same_node=True`（`.reader-content` は差し替わっていない）。
- `scroll` イベントのログは `top: 0` のみで、`top: 2375` の記録が無い。
- 成功時は `top: 2375` の記録がある。

ここから、スクロール設定の直後に**同期的に** 0 に戻されていると推論した。
テストの操作手順（`#back` で ch1 へ → 即座に `#to-ch2-part` で ch2 の
フラグメントへ）を追った結果、原因は以下と特定された。

- `render_chapter` は位置適用を `apply_position_after_render` で非同期
  （`setTimeout(0)`）にスケジュールする。
- 連続した章移動では、**前の章（ch1）の位置適用コールバック**が
  新しい章（ch2）の描画の後に実行されることがある。
- 前の章の適用は `fragment=None` のため `scroll_content_to_top()` を呼び、
  新しい章のフラグメントスクロールを 0 に上書きしていた。

## 決定

- `PositionApplyCtx` に `generation`（章描画の世代号）と
  `current_generation`（共有カウンタ）を追加する。
- `render_chapter` が描画のたびに世代号をインクリメントし、ctx に渡す。
- `apply_position_frame` のコールバック先頭で世代を照合し、
  現在の世代と異なれば何もせず破棄する。
- これで、古い章の位置適用（特に先頭リセット）が新しい章に効かないように
  する。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 世代号で古い適用を破棄（採用） | 非同期コールバックの競合を構造的に解消できる |
| E2E の待ち時間を延ばす | 競合は残り、ランダムに失敗し続ける |
| `setTimeout` を同期的にする | 画像レイアウト待ちと両立しない |
| retry 回数をさらに増やす | 古い適用が後に走るため根本解決にならない |

## 影響

- 連続した章移動でも、位置適用が正しい章にのみ反映される。
- 既存の位置復元・フラグメント移動の挙動は変わらない。
- 追加依存は無く、既存の `Rc<Cell<_>>` による状態管理の範囲。
