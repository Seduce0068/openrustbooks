## 背景

ADR-0138 の 5 回スモークは位置復元系全回成功だったが、
統計的には 10〜20% のフレーク率を否定できなかった。
ADR-0046 / 0054 の前例に従い 10 回連続実行を行った。

## 実行結果（extended-e2e-runner）

- `trunk build --offline` 成功（生成物のみ更新、ソース無変更）。
- 10 回の結果:

| 回 | 結果 | 備考 |
| --- | --- | --- |
| 1, 2 | 229/0 | 成功 |
| 3 | 228/1 | `有効時は巨大画像が 2000px 以下に縮小される`（naturalWidth=4500） |
| 4〜9 | 229/0 | 成功 |
| 10 | 0/1 | `Reader ルートが表示される`（20 秒待ってもマウントせず早期 abort、expected 229 vs executed 1） |

- 位置復元系 4 チェック（`位置の適用は画像の読み込み完了を待つ`、
  `フラグメント付きの位置が復元される`、
  `画像読み込み後も復元位置が同じ内容を指す`、
  `画像を含む章でもスクロール位置が復元される`）は、
  実行された第 1〜9 回ですべて ok。第 10 回は早期 abort のため未実行。
- 再確認として `./scripts/verify.sh` を実行し、229/0 成功。

## 決定

- 位置復元系は **9 回連続 0 失敗**をベースラインとして記録する。
- 第 10 回の早期 abort と第 3 回の画像縮小フレークは、
  位置復元ロジックとは切り分けて個別の未決定とする。
- 画像寸法予約の実装後、同じ 229 チェックを再実行し、
  下記閾値と比較する約束を固定する。

## 閾値テーブル（現状）

| チェック | 閾値 |
| --- | --- |
| 復元後のスクロール位置が保存値と一致する（非画像） | 2px 以下 |
| 位置の適用は画像の読み込み完了を待つ（適用スクロール抽出窓） | 50px 以下 |
| 画像読み込み後も復元位置が同じ内容を指す | 30px 以下 |
| 画像を含む章でもスクロール位置が復元される | 30px 以下 |

## 統計的限界（extended-e2e-auditor）

- フレーク率 p=0.1 で 10 回成功する確率は約 34.9%、
  p=0.2 なら約 10.7%（**推測**による二項計算）。
- 10 回 0 失敗でもフレーク率 0 は否定できない（上限約 25.9%）。
- p=0.2 を 20 回で否定できるが、p=0.1 の否定には 29 回以上が必要（推測）。

## 検証

- 全単体テスト core 188 + desktop 56 + web 2、wasm-test 3、
  audit 脆弱性 0 件を維持。
- `./scripts/verify.sh` 再確認 229/0。
- CI は billing issue で実行不可（ローカル検証で代替）。
