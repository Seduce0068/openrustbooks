## 背景

ADR-0017・ADR-0024 までで移動履歴はメモリと localStorage に保持され、
戻る・進むボタンで移動できたが、過去の位置へ直接ジャンプする手段が無かった
（ADR-0017 の未決定「履歴一覧の UI」）。戻る・進むを繰り返して目的の位置まで
たどる操作は、履歴が長いほど手間になる。

## 決定

### 履歴一覧のドロップダウン

- ツールバーに `<select id="reader-history" aria-label="History">` を置く。
- 各エントリのラベルは「章のタイトル + フラグメント」（フラグメントが無い
  場合は章のタイトルだけ）。章のタイトルは目次表示用のインデントを除いた
  本文側のタイトルを使う。
- 現在位置のエントリが選択状態になる。
- 選択を変えると、その履歴エントリの章・フラグメント・スクロール位置へ
  移動する（履歴の現在位置も更新する）。
- 履歴が 1 件以下のときは disabled にする。

### ジャンプ処理の共通化

戻る・進む・一覧選択は同じ処理（移動前の位置を現在エントリへ記録 →
履歴インデックス更新 → 履歴の保存 → 章の再描画）を使うため、
`jump_to_history(new_index)` に共通化した。戻るは 1 つ前、進むは 1 つ後の
インデックスでこの関数を呼ぶだけになる。

### 履歴一覧のデータ

UI 用に履歴エントリの `(履歴インデックス, 章インデックス, フラグメント)`
一覧を signal で保持し、`sync_history` で履歴の変更のたびに更新する。
ラベルは表示時に章一覧と組み合わせて作るため、章が変わっても
signal の再計算だけで追従できる。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| ドロップダウン（採用） | 追加依存なし、キーボードで完結する |
| 履歴パンくずリスト | 履歴が長いと横スペースを占有する |
| 一覧モーダル | 操作が 2 段階になり手間が増える |

## 影響

- 過去の位置へ直接ジャンプできる。
- 履歴の保存・復元の仕組み（ADR-0024）は変わらない。
- 追加依存は無く、既存の `web-sys` 機能の範囲で実装している。
- 戻る・進むの実装が `jump_to_history` に共通化され、重複が減った。

## 検証

- ヘッドレス Chrome 157 と `tools/verify-web-reader.py` の E2E 114 項目が
  3 回連続で成功。履歴一覧について、ドロップダウンの存在、リロード直後の
  履歴 1 件、章 2 回移動で 3 件になること、一覧から最初のエントリへの
  ジャンプを確認した。
- `cargo test --all-targets --locked` は 119 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
