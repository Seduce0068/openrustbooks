## 背景

章フィルター（ADR-0078）はマウスで入力欄をクリックする必要があった。
キーボード操作を補完するため、`/` でフィルターへフォーカスする。

## 決定

- `/` キーで `#reader-chapter-filter` にフォーカスする。
- 入力欄にフォーカスがあるときは既存の規則（キーを奪わない）を維持する。
- ヘルプダイアログ（ADR-0075）に `/` の項目を追加する。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| `/` でフォーカス（採用） | 検索の一般的なショートカットで覚えやすい |
| `f` でフォーカス | 既存の `d` などとの競合はないが、直感的でない |
| ショートカットなし | マウス操作が必要でキーボード-only 使い勝手が悪い |

## 影響

- キーボードだけで章を検索して移動できる。
- 既存のキーボード操作には影響しない。
- 追加依存は無い。

## 検証

- ヘッドレス Chrome 157 と `tools/verify-web-reader.py` の E2E 212 項目が
  5 回連続で成功。
- `/` キーでフィルター入力にフォーカスすること、ヘルプに `/` の記載が
  あることを確認した。
- `cargo test --all-targets --locked` は 125 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI は billing issue で実行不可（ローカル検証で代替）。
