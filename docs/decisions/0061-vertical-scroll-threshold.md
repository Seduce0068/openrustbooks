## 背景

ADR-0056 の未決定「縦スクロール判定閾値（30px）の設定化」。
横スワイプ閾値は設定化済みだが、縦移動をスクロールとみなす 30px は
ハードコードで、端末や利用者に合わせられなかった。

## 決定

- `ReaderSettings` に `verticalScrollThreshold` を追加する。既定値 30、範囲 10〜80px。
- 既存の設定 JSON にキーが無い場合は既定値 30 として読む（後方互換）。
- 範囲外の値は `normalized()` で 10〜80 にクランプする。
- 設定の保存・エクスポート・インポートに含まれる（横スワイプと同じ仕組み）。
- ツールバーに数値入力（`<input id="reader-vertical-threshold">`）を置き、
  変更で即座に保存・反映する。
- 縦スクロール判定に設定値を使う。横スワイプ閾値（既定 50）は維持する。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 設定で変更可能にする（採用） | 横スワイプと一貫した操作感の調整ができる |
| ハードコードのまま | 縦スクロールと誤判定される場合を調整できない |
| 横スワイプと同じ値にする | 横と縦で適切な閾値は異なる |

## 影響

- 縦スクロールと章移動スワイプの誤判定を利用者が調整できる。
- 表示設定の JSON に `verticalScrollThreshold` が 1 つ増える。旧データは既定値で読める。
- 追加依存は無く、既存の `web-sys` 機能の範囲で実装している。

## 検証

- ヘッドレス Chrome 157 と `tools/verify-web-reader.py` の E2E 179 項目が
  5 回連続で成功。縦スクロール閾値入力の存在、変更値（60）の保存、
  範囲外（999）の 80 へのクランプを確認した。
- `cargo test --all-targets --locked` は 124 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI は billing issue で実行不可（ローカル検証で代替）。
