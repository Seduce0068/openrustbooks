## 背景

ADR-0073 の未決定「JPEG 品質変更による実際のファイルサイズ・画質の定量比較」。
品質設定が encoder options として実際に効いているか、ファイルサイズの差で
検証できるかを調査した。

## 調査結果

- E2E で Pillow のノイズ JPEG（4500x100）を含む EPUB を生成し、
  品質 50 と 100 で縮小して Blob サイズを比較した。
- 両方とも同じサイズ（54750 バイト）だった。
- デバッグで確認した事実:
  - 設定値は正しく Rust 側へ届いている（quality 50 / 100）。
  - 縮小後の自然サイズは 2000x44 で、MIME は `image/jpeg`。
  - `canvas.toBlob()` の戻り値は `Ok`。
  - ブラウザ上で直接 `putImageData` したランダムノイズを
    quality 0.1 / 1.0 でエンコードすると 9203 / 280642 バイトとなり、
    Canvas の JPEG エンコーダ自体は品質を正しく反映する。
- したがって、差が出ない理由は**縮小時の `drawImage` ダウンサンプリングに
  ある**。元 JPEG は既に高周波が圧縮で失われており、さらに 4500→2000 に
  縮小すると残留ノイズも平均化され、品質を変えても出力サイズが
  ほぼ一定になる。

## 決定

- 不安定なファイルサイズ比較テストは追加しない。
- 品質設定が保存され、縮小処理へ渡ることは既存 E2E
  （設定の保存とクランプ）で確認済みとみなす。
- 品質設定の目的は「画質を下げずに再エンコードすること」であり、
  ファイルサイズ削減ではないことを ADR に明記する。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 知見を記録しテストは追加しない（採用） | 画像内容依存の不安定なテストを避けられる |
| ノイズを増やして差を出すよう調整 | 現実の EPUB 画像を代表せず、テストが脆くなる |
| 品質設定を削除 | 画質維持のための設定として有用 |

## 影響

- プロダクションコードの変更は無い（調査のみ）。
- 既存の 125 テスト、E2E 202 項目はそのまま通る。
- 追加依存は無い（Pillow は既存の開発環境のものを一時的に利用）。
