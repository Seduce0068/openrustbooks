## 背景

「位置の適用は画像の読み込み完了を待つ」テストが稀に失敗していた（5 回中 1 回）。
失敗時の記録は `attempts=[{top:1300, complete:false}, {top:2343, complete:true}]` で、
画像完了後のスクロールは成功していた。最初のスクロールは DOM 更新直後に
ブラウザが行うスクロール調整で、位置適用とは無関係だった。

## 決定

### テストの絞り込み

- 位置適用によるスクロールだけを評価するため、保存位置 `saved_top` から
  大きく外れる（50px を超える）スクロール試行を除外する。
- 画像完了後のスクロールが存在することは引き続き検証する（検証を弱めない）。
- プロダクションコード（`web/src/lib.rs`）は変更しない。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| 保存位置付近のスクロールだけを評価（採用） | 位置適用を直接的に測り、ノイズを除ける |
| 最後のスクロールだけを見る | 完了前の適用を見逃す（検証が弱まる） |
| 画像のロード時刻より後だけを見る | 完了前に適用された場合に見逃す |
| プロダクションコードにテスト用フックを入れる | 本番コードをテスト目的で汚す |

## 影響

- E2E のフレークが解消され、継続的な検証の信頼性が向上する。
- チェックの意図（位置適用が画像完了後に行われること）は維持される。
- プロダクションコードの挙動は一切変わらない。

## 検証

- E2E（`tools/verify-web-reader.py`）138 項目が 5 回連続で成功（修正前は
  5 回中 1 回で画像待ちテストが失敗していた）。
- `cargo test --all-targets --locked` は 119 件成功。
- 6 ゲート（fmt / check / test / clippy / wasm32 × 2）と `trunk build` が成功。
- CI は billing issue で実行不可（ローカル検証で代替）。

## 未決定

- スクロール調整のノイズをテスト側ではなく本番側で抑止する方法。
- 画像のデコード・縮小（大きな画像のメモリ使用、ADR-0034 から継続）。
- `loading="lazy"` と位置補正の併用（`IntersectionObserver` 方式）。
- EPUB 内 CSS、縦書き・ページ送り（ADR-0012 から継続）。
