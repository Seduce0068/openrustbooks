## 目的と背景

本や文書の閲覧と、テキスト系ファイルの編集を一つのアプリで行う。
デスクトップだけでなくブラウザからも利用し、
Google Driveなどに保存した文書を扱えるようにする。

利用者はObsidianでフォルダのインポートをしづらいと感じている。
フォルダを開くまでの操作と、保存場所へのアクセスの容易さを重視する。

## 記録の読み方

- 要件: 利用者が明示した、実現したい機能や方向性。
- 決定: 会話で採用することが明示された技術方針。
- 提案: 実現方法や検証方法の案。合意済みの仕様とは区別する。
- 未決定: 実装や対応を約束する前に具体化が必要な事項。

要件として記載されていても、初版ですべて実装することは未決定。
本書は実装状況を表さない。

## 利用者要件

### REQ-001: Rustの活用

Rustを積極的に活用する。
原READMEの「限りなくrustで本とかのリーダー、できればエディタ」
という方向性を引き継ぐ。

すべての依存部品をRustだけで構成する制約は合意していない。
JavaScriptの描画・編集部品を採用するかは未決定。

### REQ-002: 複数形式の閲覧

EPUB・ZIP・PDF・TXT・Markdownを扱うリーダーを提供する。

| 形式 | 求める役割 | 詳細が未決定の部分 |
| --- | --- | --- |
| EPUB | 電子書籍の閲覧 | 対応バージョン、固定レイアウト、DRM |
| ZIP | アーカイブ内のコンテンツ閲覧 | 画像集、混在文書、暗号化、入れ子 |
| PDF | PDFの閲覧 | 注釈、フォーム、暗号化、OCR |
| TXT | テキストの閲覧・編集 | 文字コード、改行コード、大容量 |
| Markdown | 文書の閲覧・編集 | 方言、拡張構文、プレビュー互換性 |

PDFやEPUBの本文編集は、現時点で明示された要件には含めていない。
将来対応を禁止するものではない。

### REQ-003: テキスト編集

TXT・Markdownなどのテキスト系ファイルについて、
リーダーをエディタとしても利用できるようにする。

保存操作、自動保存、Undo、検索・置換などの具体的な範囲は未決定。

### REQ-004: デスクトップとブラウザ

デスクトップアプリとして利用でき、ブラウザからも利用できるようにする。

デスクトップ版のOS WebView方式は決定済み。
対象OS・ブラウザ・最低バージョンと、
両者で同等に提供する機能範囲は未決定。

### REQ-005: フォルダ操作の容易さ

フォルダを簡単に開いて、文書を扱えるようにする。
インポートや再登録が利用開始の障壁にならない体験を目指す。

既存フォルダの直接参照を基本にする案がある。
直接編集とアプリ内へのコピーの使い分けは、まだ仕様として確定していない。

### REQ-006: Google Driveなどとの連携

Google Driveと連携して文書を扱う。
他のクラウドストレージへの拡張も構想に含める。

Google Drive以外の対象サービス、OAuth権限、
双方向の自動同期、オフライン利用、競合解決方式は未決定。
「クラウドへの読み書き」と「自動同期」は別の機能として扱う。

### REQ-007: フォルダ・アーカイブでの保存

Google Driveなどに、フォルダまたはアーカイブとして保存できるようにする。

アーカイブ内の編集を直接保存するか、
展開先へ保存するか、別アーカイブとして再作成するかは未決定。
日常編集にはフォルダ、持ち運びにはZIPを使う案がある。

### REQ-008: エクスプローラーからのアクセス

保存したフォルダに、エクスプローラー上で簡単にアクセスできるようにする。

「エクスプローラー」の意味は、次の操作を区別して具体化する必要がある。

- アプリ内のファイルツリーでフォルダを開く。
- OSのファイルマネージャーでローカルの保存場所を開く。
- Google DriveのWeb画面でクラウドの保存場所を開く。

### REQ-009: Markdown支援機能

次の機能群を利用したいという要望がある。

| 機能群 | 要望 | 実現方法の候補 |
| --- | --- | --- |
| Markdown Preview Enhanced（MPE） | 高機能プレビュー | Crossnote再利用、機能単位の実装 |
| markdownlint | Markdownのlint | 既存エンジンの組み込み |
| Markdown All in One | Markdown編集支援 | ショートカット、目次、リスト操作 |

VS Code拡張をそのまま実行する互換環境の実装は決定していない。
どの機能が必須か、完全互換が必要かを具体化する。

## 検証条件の提案

以下は要件を具体化するための候補であり、承認済みの受け入れ基準ではない。

| 対象 | 検証したい体験 |
| --- | --- |
| フォルダ | 既存の文書フォルダを選択し、階層を辿って開ける |
| テキスト編集 | 日本語を編集・保存し、他のエディタで結果を読める |
| Markdown | 相対パスの画像・リンクをプレビューで解決できる |
| リーダー | 対応サンプルを開き、目次・ページ・章を移動できる |
| ZIP | 内部の対応ファイルを選び、内容を閲覧できる |
| ブラウザ | 同じ文書を表示し、利用可能な保存経路で保存できる |
| Drive | 選択した場所へ保存し、Drive上でも内容を確認できる |
| OS連携 | デスクトップ版からローカルの保存場所を開ける |

## 追加検討する品質要件

次の項目は設計上の提案。初版の必須条件や数値目標は未決定。

- 保存失敗時に、未保存の編集内容を失わない。
- 外部アプリの更新やクラウドの競合を検知して扱う。
- 日本語IME、タッチ操作、キーボード操作を検証する。
- 長い文書、大きなPDF・ZIPについて対象サイズを定めて検証する。
- EPUB・MarkdownのHTMLと、アプリの特権操作を分離する。
- アーカイブ処理でパスの逸脱と過大な展開を扱う。
- 実際の対象WebView・ブラウザで表示と操作を確認する。

## 優先して具体化する事項

1. 最初の対象OS・ブラウザと、スマホの利用範囲。
2. 閲覧体験。スクロール、ページ送り、縦書き、文字サイズなど。
3. 既存フォルダの直接編集と、インポートの使い分け。
4. MPE・Markdown All in Oneで必須とする機能。
5. 初版の対応形式と、保存先の優先順。
6. フロントエンド、Tauriのバージョン、各ライブラリの採用。
7. Google Driveの手動保存・自動同期・オフライン対応の範囲。
8. EPUB・PDF・ZIPの高度な機能の対応範囲。
